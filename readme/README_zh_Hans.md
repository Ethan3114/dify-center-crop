# 等比中心裁切：Dify 云端 Agent 使用说明

这是工具插件版，裁切在 Dify 的插件运行环境完成，无需另开图片处理服务器。默认保留中央宽高各 85% 的画面；对当前 1024×1024 原图，四边各裁掉 77 像素，输出 870×870。直接裁切原始像素，不缩放，不新增留边。

## 上传安装

在 Dify「安装插件 → 通过 GitHub 安装」输入 `https://github.com/Ethan3114/dify-center-crop`，选择 `v0.0.4` 及 `center_crop-0.0.4.difypkg` 附件安装。详见 [源码仓库](https://github.com/Ethan3114/dify-center-crop)。

当前插件作者标识为 `ethan3114`（全小写），对应 GitHub 账户 `Ethan3114`；如果仓库换到其他用户下，必须同步修改 manifest、provider 和 tool YAML 里的作者并重新打包。

也可以下载 Release 中的安装包，进入 Dify 云端工作空间的「插件」，选择「安装插件 → 通过本地文件安装」，上传 `center_crop-0.0.4.difypkg`。无需填写第三方 API Key。

本包未经过 Marketplace 审核或官方签名，也未在你的云端工作空间实际安装。若工作空间拒绝未签名包，保留错误信息；云端不能修改自部署版的 `.env` 设置。可在提供调试入口的工作空间进行临时远程调试；长期使用需要工作空间允许私有安装，或通过 Marketplace 审核发布。远程调试需要本地进程持续运行，不能代替长期云端部署。

## 推荐：Chatflow 内的 Agent 节点

1. 新建 Chatflow，在输入配置里启用图片上传。测试时仅上传原图。
2. 添加「Agent」节点，并选择支持工具调用的模型和策略。
3. 在 Agent 的工具列表里添加「等比中心裁切」。
4. 工具输入 `images` 通过变量选择器绑定本次聊天上传文件 `sys.files`。如果处理的是上游图片生成工具的结果，绑定该节点的 `files`。不要让语言模型编造文件对象。
5. 工具参数 `ratio` 设为手动输入 `0.85`。这样每次稳定保留宽高各 85%；也可以切换为由 Agent 根据用户需求推断。
6. Agent 的任务输入引用本轮用户问题；系统指令使用下方示例。
7. 在「回答」节点使用变量选择器引用 Agent 的图片/文件输出（通常为 `files`）。如果只能看到文本输出，先检查所选 Agent 策略是否保留工具的文件消息，再配置文件输出。不能靠模型编造一个下载链接。
8. 上传原图并输入「将这张图四边向内裁切，保留中央 85%」，检查返回 PNG 是否为 870×870。

不同 Agent 策略和云端版本的文件呈现可能不同。上面的文件传递和对话显示步骤尚未在你的账户内验证。工具本身通过 Dify SDK 返回 PNG 文件消息和尺寸 JSON。

## Agent 指令

```text
你是图片裁切助手。用户要求从四边向内裁切时，调用「等比中心裁切」工具处理已绑定的输入图片。
默认保留原宽高的 85%，ratio=0.85，即每边约裁掉 7.5%；这不是把画面缩小后加留白。
返回工具生成的 PNG 图片文件，简短说明输出尺寸。不得声称已经处理，除非工具调用成功。
用户没有提供图片时，提醒其上传图片。不要编造图片地址、文件对象或下载链接。
```

## 独立 Agent 应用

安装后可以在 Agent 应用的工具列表中查找本工具。如果该界面支持为 `images` 绑定本轮上传文件，就按上述方式配置；若只提供静态配置而无法绑定动态上传图片，使用 Chatflow 内的 Agent 节点。它仍由 Agent 决定何时调用工具，图片通过工作流变量传入。

## 输出

- `files`：裁切后的 PNG 图片文件。
- `json`：输出文件名、宽、高、比例及操作名称。
- 不依赖外部图片处理接口或生成模型。
